## 2. Jump-to Navigation Fix (P.K.S. with Samam Range Resolution)

**Problem**: The "Jump to" input accepted `P.K.S` format (e.g., `6.11.33`), but it navigated to `#sama-33` which doesn't exist. The actual Samam entries use a range-based mapping where `#sama-10` covers Samams 31–33.

**Solution**: Updated `handleJump` in `main.js` to:
1. Parse the sidebar `.sama-link` elements which display ranges (e.g., `1–2`, `3–5`, `31–33`)
2. Match the input Samam number against these ranges
3. Navigate to the correct `#sama-N` anchor
4. Fall back to `#sama-{N}` if no range match is found

**Files modified**:
- `src/generate_website.py` — embedded JS template in `_generate_js()`
- `docs/js/main.js`
- `docs/samhita/js/main.js`
- `docs/aaranam/js/main.js`
- `docs/aranam/js/main.js`

## 5. Full-Text Search Implementation

**Problem**: No search functionality existed beyond the "Jump to" input.

**Solution**: Implemented a full-text search modal with the following features:

### Search Index (`search-index.js`)
- Generated as a JavaScript file (not JSON) to avoid `file://` CORS issues
- Contains two versions of each text:
  - **Clean text** — stripped of HTML tags for matching
  - **HTML text** — preserved with swara marks for display
- Indexed fields: mantra text, rik text, title, metadata, Rishi, Devata, Chandas
- Scoring system: Mantra (10) > Rik (8) > Rishi (7) > Devata (6) > Title (5) > Chandas (4) > Metadata (3)

### Search Modal
- Opens via sidebar "अन्वेषणम् (Search)" button, top nav "Search" link, or pressing `/`
- Results display with highlighted matches, showing the original HTML with swara marks
- Clicking a result navigates to the corresponding Samam
- Close with `Escape`, clicking overlay, or `×` button
- Debounced input (250ms) for performance

### CSS
- Modal overlay with backdrop blur
- Scrollable results area within `80vh` modal
- Highlighted search matches with `<mark>` styling
- Font sizes: search input `1.2rem`, search results `1.2rem`

**Files modified**:
- `src/generate_website.py` — added `_generate_search_index()`, `_clean_text_for_search()`, search modal HTML in all page templates, search CSS
- `docs/samhita/search-index.js` — generated (722 entries)
- `docs/aaranam/search-index.js` — generated (148 entries)

## 6. Search Result Click Navigation Fix

**Problem**: Clicking on a search result from a kandah page produced a "File not found" error because the relative path `kandah/supersection_N/N.html` was resolved relative to the current page path (e.g., `kandah/supersection_1/1.html` → `kandah/supersection_1/kandah/supersection_N/N.html`).

**Solution**: Added depth detection in the JS to prepend `../../` when on kandah pages:
- Detects `/kandah/` in `window.location.pathname`
- Prepends `../../` to all search result links when on a kandah page

**Files modified**:
- `src/generate_website.py` — embedded JS in `_generate_js()`

---

## 7. Search Result Multi-Field Display

**Problem**: Search results only showed the highest-scoring matching field (e.g., Mantra), hiding other matching fields like Rik even when they also matched the query.

**Solution**: Changed the search result rendering to display **all matching fields** per result:
- Each matched field (Mantra, Rik, Rishi, Devata, etc.) is shown with its own label (in Devanagari: मन्त्र, ऋक्, etc.)
- Each field shows the highlighted match text
- Scoring still determines result ordering, but all matches are visible

**Files modified**:
- `src/generate_website.py` — `performSearch()` now tracks all matched fields, result rendering loops through `matchedFields` array
- CSS: added `.search-result-field` and `.search-result-field-label` styles
